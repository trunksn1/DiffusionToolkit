# Album Assignment - Correct Workflow Explanation

## Database Structure Understanding

### Civitai Database (`civitai_state.db`)

**downloads table:**
```
civitai_id       INTEGER (auto-increment) - Civitai's internal ID
local_path       TEXT                      - Full path where image was downloaded
status           TEXT                      - Download status ('completed', etc.)
updated_at       TIMESTAMP                 - When record was updated
```

**IMPORTANT:**
- `civitai_id` is Civitai's internal ID - has **NOTHING** to do with Diffusion Toolkit's Image.Id
- `local_path` is the **ONLY** useful column for matching with Diffusion Toolkit

### Diffusion Toolkit Database (`Diffusion.Toolkit.db`)

**Image table:**
```
Id               INTEGER (auto-increment) - Diffusion Toolkit's image ID
Path             TEXT                      - Full path to the image file
FileName         TEXT
CreatedDate      TIMESTAMP
... other columns ...
```

**Album table:**
```
Id               INTEGER (auto-increment) - Album ID
Name             TEXT                      - Album name
LastUpdated      TIMESTAMP
```

**AlbumImage table (junction table):**
```
AlbumId          INTEGER - Foreign key to Album.Id
ImageId          INTEGER - Foreign key to Image.Id
```

## The Correct Workflow

### Step 1: BEFORE Download Starts

**Save the last civitai_id from Civitai database:**

```csharp
// Query Civitai database
var lastId = connection.ExecuteScalar<int>("SELECT COALESCE(MAX(civitai_id), 0) FROM downloads");
// Store it: _lastDownloadId = lastId;
```

**Example:** Last download in database has `civitai_id = 5391`, so we save `_lastDownloadId = 5391`

**Purpose:** This ID is used ONLY to identify NEW downloads in the next step. It's NOT used for anything else.

---

### Step 2: User Runs Download

Python script downloads new images, Civitai database gets new entries:

```
civitai_id | local_path                           | status
-----------|--------------------------------------|----------
5392       | E:\Images\Civitai\new_image_1.png   | completed
5393       | E:\Images\Civitai\new_image_2.png   | completed
```

---

### Step 3: AFTER Download Completes - Find NEW Downloads

**Query Civitai database for new downloads:**

```csharp
var query = "SELECT local_path FROM downloads WHERE status = 'completed' AND civitai_id > ?";
var results = connection.Query<CivitaiDownloadRecord>(query, _lastDownloadId);
// _lastDownloadId = 5391, so this returns rows with civitai_id > 5391
```

**Results:**
```
local_path: E:\Images\Civitai\new_image_1.png
local_path: E:\Images\Civitai\new_image_2.png
```

**Purpose:** Using `civitai_id > _lastDownloadId` ensures we ONLY get NEW downloads, not all 5391+ existing downloads.

**Store these paths:**
```csharp
var downloadedPaths = new List<string>();
foreach (var record in results)
{
    downloadedPaths.Add(record.local_path);
}
// downloadedPaths now contains the 2 new file paths
```

---

### Step 4: Refresh/Scan Diffusion Toolkit Database

**Trigger Diffusion Toolkit's scan function:**

```csharp
await ServiceLocator.ScanningService.ScanWatchedFolders(...);
```

**What this does:**
- Scans the watched folders configured in Diffusion Toolkit
- Finds new images that weren't in the database before
- Adds them to the Image table with auto-generated IDs

**After scan, Image table has:**
```
Id      | Path                                  | CreatedDate
--------|---------------------------------------|------------------
123456  | E:\Images\Civitai\new_image_1.png    | 2026-01-09 20:30
123457  | E:\Images\Civitai\new_image_2.png    | 2026-01-09 20:30
```

**CRITICAL:** The `Id` values (123456, 123457) are generated by Diffusion Toolkit's auto-increment. They have NOTHING to do with Civitai's `civitai_id` (5392, 5393).

---

### Step 5: Match Paths to Get Diffusion Toolkit Image IDs

**Query Diffusion Toolkit's Image table using the paths we got from Civitai:**

```csharp
var imageIds = ServiceLocator.DataStore.GetImageIdsByPaths(downloadedPaths).ToList();
```

**What GetImageIdsByPaths does:**
```csharp
// Input: downloadedPaths = ["E:\Images\Civitai\new_image_1.png", "E:\Images\Civitai\new_image_2.png"]

// Query:
SELECT Id FROM Image WHERE Path IN (
    'E:\Images\Civitai\new_image_1.png',
    'E:\Images\Civitai\new_image_2.png'
)

// Output: imageIds = [123456, 123457]
```

**Purpose:** Convert file paths to Diffusion Toolkit's Image IDs.

---

### Step 6: Insert into AlbumImage Table

**Get the Album ID from the album name the user selected:**

```csharp
var album = ServiceLocator.DataStore.GetAlbumByName(albumName);
// Example: album.Id = 174
```

**Insert entries into AlbumImage:**

```csharp
ServiceLocator.DataStore.AddImagesToAlbum(album.Id, imageIds);
```

**What this inserts:**
```sql
INSERT INTO AlbumImage (AlbumId, ImageId) VALUES
(174, 123456),
(174, 123457)
```

**Result:** Images are now assigned to the album!

## Key Points

### 1. Two Separate ID Systems

**Civitai `civitai_id`:**
- Purpose: Track downloads in Civitai's database
- Used ONLY to identify NEW downloads (civitai_id > last_id)
- NOT stored or used in Diffusion Toolkit

**Diffusion Toolkit `Image.Id`:**
- Purpose: Identify images in Diffusion Toolkit's database
- Auto-generated when scan adds the image
- Used in AlbumImage table to link images to albums

**These IDs are COMPLETELY SEPARATE!**

### 2. The Matching Key is `Path` / `local_path`

**The ONLY way to connect the two databases is through the file path:**
- Civitai database has `local_path`: `E:\Images\Civitai\image.png`
- Diffusion Toolkit has `Path`: `E:\Images\Civitai\image.png`
- They must match EXACTLY (same string, character for character)

### 3. Why We Use civitai_id

**We use civitai_id ONLY for filtering:**
- Get the max civitai_id BEFORE download: tells us what already existed
- Query WHERE civitai_id > max: gives us ONLY new downloads
- This is more reliable than timestamps (no format/timezone issues)

**We DON'T use civitai_id for:**
- Matching with Diffusion Toolkit (we use paths)
- Storing in Diffusion Toolkit (it doesn't care about Civitai IDs)
- Any other purpose

## Why The Previous Attempt Failed

### Old Approach (BROKEN):
```csharp
_downloadStartTime = DateTime.Now;
var query = "SELECT local_path FROM downloads WHERE updated_at >= ?";
var results = connection.Query<CivitaiDownloadRecord>(query, _downloadStartTime);
```

**Problems:**
1. DateTime vs TIMESTAMP string format mismatch
2. Timezone issues (local time vs UTC)
3. SQLite-net conversion issues
4. Result: Query returned ALL 5391 downloads, not just new ones

### New Approach (FIXED):
```csharp
_lastDownloadId = MAX(civitai_id);  // Get before download
var query = "SELECT local_path FROM downloads WHERE civitai_id > ?";
var results = connection.Query<CivitaiDownloadRecord>(query, _lastDownloadId);
```

**Why it works:**
1. Simple integer comparison: `5392 > 5391` ✓
2. No format issues (comparing ints, not strings)
3. No timezone issues (just sequential numbers)
4. Result: Query returns ONLY new downloads (civitai_id = 5392, 5393)

## Summary

**The Fix:**
1. Use `civitai_id` to filter NEW downloads (not for matching)
2. Use `local_path` (from Civitai) matched with `Path` (in Diffusion Toolkit) to find Image IDs
3. Use those Image IDs to create AlbumImage entries

**What civitai_id is used for:**
- ✅ Identifying NEW downloads (civitai_id > last_id)
- ❌ NOT for matching with Image.Id (completely different systems!)

**What local_path/Path is used for:**
- ✅ Matching between Civitai downloads and Diffusion Toolkit images
- ✅ The ONLY connection between the two databases

**The implementation already does this correctly!** The code:
1. Saves last civitai_id
2. Queries WHERE civitai_id > last_id
3. Gets local_path values
4. Scans to add images to Diffusion Toolkit
5. Matches paths to get Image IDs
6. Inserts into AlbumImage with correct IDs
